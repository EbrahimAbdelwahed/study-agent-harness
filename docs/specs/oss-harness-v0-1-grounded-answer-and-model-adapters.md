## Goal

Execute the same versioned `grounded_answer@1` skill and `grounded_answer_flow@1` through the existing generic playbook engine with deterministic prompt composition, fail-closed citation validation, a scripted offline model, and an opt-in generic OpenAI-compatible transport adapter.

## Problem

Retrieval and citation resolution are implemented, but the harness cannot yet turn evidence into a validated answer. The generic engine currently places prompt bindings in local request metadata rather than composing the pinned prompt before `ModelPort`, which would force a real adapter to invent prompt behavior. There is also no reusable model-adapter conformance implementation.

## Users

- Library authors executing grounded study behavior without adopting a provider SDK or agent framework.
- Adapter authors proving conformance without forking prompt or grounding policy.
- Researchers comparing models while holding skill, playbook, prompt, retrieval, and validators fixed.

## In Scope

- Canonical six-layer prompt contract and deterministic composition before `ModelPort`.
- Built-in `grounded_answer@1.0.0`, prompt `grounded_answer.v1@1.0.0`, and `grounded_answer_flow@1.0.0`.
- Canonical evidence envelope with stable opaque handles derived from trusted chunk identity.
- Model-facing answer-draft schema that accepts evidence handles, never source metadata.
- Deterministic evidence-sufficiency and grounded-answer-integrity validators.
- Provider-neutral model invocation provenance sufficient for persisted answer provenance.
- Strict FIFO scripted model adapter and reusable model adapter contract tests.
- Dependency-free opt-in OpenAI-compatible chat-completions adapter with injected HTTP transport, safe errors, redaction, and no default network calls.
- End-to-end offline playbook/eval fixtures for supported, insufficient, conflicting, malformed, forged-citation, course-profile, and prompt-injection cases.

## Out of Scope

- Session domain events and final answer persistence, typed public study tools, CLI/export, live network calls in default tests, streaming HTTP, true in-flight cancellation, retries, provider SDKs, Tau, vector retrieval, semantic entailment/conflict inference, or product work.
- Provider/model-name branches, provider-specific prompt text, secrets in domain/run state, or transmitting local `ModelRequest.metadata`.

## Domain and Interface Contracts

- `ComposedPrompt`: pinned prompt reference, canonical messages, ordered layer records, and SHA-256 fingerprint.
- `PromptComposer`: generic runtime port that composes a pinned prompt from declared bindings and output schema before model invocation.
- `GroundedAnswerDraft`: strict JSON object containing status, typed segments, text, and trusted `evidence_ids` only.
- `EvidenceEnvelope`: canonical JSON representation of one retrieval result; handles are unique and deterministically derived from chunk IDs.
- `ModelInvocation`: adapter ID/version, configured model ID, provider response/run ID, and optional usage; generated by adapters, never accepted from model content.
- `ModelResponse`: retains structured output and trusted invocation provenance; absent usage is represented as absent, never invented as zero.
- Adapter errors expose stable safe codes/retryability and never raw bodies, headers, messages, URLs with credentials, or chained secret-bearing exceptions.

## Prompt Behavior

Prompt layers appear exactly once and in this order:

1. immutable study/security policy;
2. structured course profile;
3. grounded-answer task instruction;
4. bounded continuation summary;
5. delimited canonical JSON evidence;
6. exact output schema.

Each layer receives only declared inputs. Missing or unused inputs fail before the model call. Structured values use canonical JSON. Evidence and continuation data are explicitly untrusted and cannot change policy, tools, permissions, or schema. The exact schema is also supplied as the portable structured-output constraint. Composition never inspects provider/model identity.

## Grounding Rules

- The model returns only evidence handles; trusted citations are reconstructed from the retrieval envelope.
- Every supported claim and synthesis has at least one supplied handle; study guidance has none.
- Every mapped citation is re-resolved against canonical content and must equal the retrieved citation and quote.
- Insufficient evidence terminates before model invocation and emits a deterministic insufficient result; persistence is deferred to the session batch.
- Trusted conflicting evidence requires `conflicting_evidence`; lexical retrieval itself never invents conflict.
- Model-provided citations, provenance, source/revision IDs, offsets, provider/model selectors, or extra properties are rejected.
- Runtime validation guarantees integrity and traceability, not semantic entailment; entailment remains eval-only.

## Model Adapter Rules

- `ModelRequest.metadata` is local audit data and is never serialized to HTTP.
- Scripted and HTTP adapters implement the same `ModelPort` conformance suite.
- Capabilities are configured structurally; adapter behavior never branches on DeepSeek, OpenRouter, endpoint host, or model name.
- The HTTP adapter accepts an explicit HTTP(S) chat-completions URL, model ID, secret credential, timeout, and declared capabilities. Import/construction performs no I/O.
- Native JSON Schema output is used only when declared. Otherwise the existing declared parse-and-validate fallback applies.
- Initial HTTP streaming/cancellation are explicitly unsupported and not advertised.
- HTTP translation and response parsing are tested through an injected fake transport using only the standard library.

## Risks and Decisions

- Prompt composition must be a generic engine seam, not a grounded-answer conditional.
- Existing historical generic playbook tests may keep their arbitrary prompt IDs; only the built-in registry uses canonical IDs.
- Full answer persistence/provenance events require the next session batch. This batch produces a fully validated canonical answer plus trusted run provenance without claiming persistence.
- `EvidenceStatus.CONFLICTING` is exercised through trusted fixtures because FTS deliberately cannot infer semantic contradiction.

## Acceptance Criteria

- [x] Identical prompt inputs produce byte-identical messages and fingerprint; six versioned layers are ordered exactly once.
- [x] Bound prompt inputs are composed before `ModelPort`; local metadata is neither semantic input nor transmitted by HTTP.
- [x] Prompt injection inside evidence or continuation cannot alter tool set, schema, or control flow.
- [x] The model can reference only stable handles from the supplied evidence set; canonical citations are reconstructed and re-resolved from trusted state.
- [x] Insufficient evidence terminates before any model call; conflicting evidence cannot become an ordinary answered result.
- [x] Invalid schema, unknown/duplicate/stale handles, forged metadata, mismatched quotes, and unsupported claims fail before a commit-capable step.
- [x] The same built-in skill/playbook request runs through scripted and OpenAI-compatible adapters without prompt/domain branches.
- [x] Scripted execution is strict, deterministic, immutable, and proves request equality.
- [x] HTTP request/response translation is fully covered offline; metadata and secret sentinels never appear in bodies, reprs, or public errors.
- [x] Default tests require no API key, network, SDK, provider, Tau, or product application.
- [x] An explicitly skipped opt-in smoke can target DeepSeek, OpenRouter, or a local compatible endpoint through configuration only.
- [x] Unit, contract, integration, eval, Ruff, mypy, architecture, and diff gates pass.

## Verification

- Unit: prompt layer validation/composition/fingerprints; evidence codecs; grounding validators; adapter translation/error/redaction.
- Contract: reusable scripted and OpenAI-compatible model-port conformance with fake transport.
- Integration: real engine + built-in skill/playbook + real prompt composer/validators + scripted external effects.
- Evals: supported, synthesis, insufficient, conflict, injection, malformed schema, unknown/old handles, altered quote, extra fields, and course terminology variation.
- Optional manual: explicit environment-gated OpenAI-compatible smoke; never part of default CI.
